## 5. 阶段补齐计划

### Phase A: 认证攻坚 (Month 1-6) — 解决 P0 差距

```
Month 1-3: CCC Digital Key 认证 → 找 DEKRA 开始预测试
Month 2-4: ISO 21434 差距分析 → 实施安全机制 → 认证测试
Month 3-6: Apple MFi 申请 → 准入评估 → 开发 → 测试
同时推进: DK Toolkit VSoC v1（安全可视化 MVP）
```

### Phase B: 工具链建设 (Month 3-9)

```
Month 3-5: yulePIN v1 — 全链路日志采集（云+App+车端）
Month 4-6: yuleRUN v1 — 自动化压测（多手机型号）
Month 5-8: OMS v1 — 生命周期管理（售前→售后）
Month 6-9: Wiggler v1 — 智能标定平台（与 yuleASR BSW 集成）
```

### Phase C: 架构升级 (Month 6-12)

```
Month 6-8: yuleHUB 从单协议网关 → 多设备集成平台
Month 6-9: 硬件参考设计（与 NXP 合作）
Month 8-12: ASPICE 正式认证 + 合规闭环
```

### Phase D: 量产验证 (Month 9-18)

```
Month 9-12: 与主机厂合作 POC（1-2家）
Month 12-15: 硬件量产 + 认证通过
Month 15-18: 首款量产车型 SOP
Month 18+: 商用车/两轮车/车队管理场景扩展
```

## 6. 结论

**核心判断：yuleDKCS 在代码层（三协议栈/Go后端）与银基对等，但在认证体系、工具链生态、硬件能力三个维度存在显著差距。**

> 银基是「产品平台」，yuleDKCS 是「代码项目」。从项目到产品需要跨越认证、工具链、硬件量产三道门槛。

**最短路径建议：**
1. **先用 yuleOSH AI pipeline 优势** — 以自动化开发效率换时间，加速 POC 交付
2. **找认证合作** — 与 DEKRA 签约 CCC 认证预测试（3个月），与 NXP 合作参考设计
3. **优先补齐 VSoC + yulePIN** — 安全+可观测性是最直接影响主机厂选型的工具
4. **Apple Wallet 不着急** — 银基花了 2 年打通苹果，这期间可以靠 ICCE/ICCOA + Android 先上车
