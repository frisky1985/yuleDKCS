# SE050 产线密钥层级与注入方案

> **版本**: 1.1.0 | **日期**: 2026-11-09
> **适用**: yuleDKCS 嵌入式车端 (NXP S32K3 + SE050)
> **安全等级**: P0-Critical (KR-IMPL-01)
> **代码基线**: `se050_scp03.c` / `se050_apdu.c` (SCP03 + PUT KEY + REPLACE KEYS)

---

## 1. 范围与边界

### 1.1 问题

SE050 出厂时 SCP03 传输密钥 (K-ENC / K-MAC / K-RMAC) 可能为默认值（全零）。若以默认密钥部署，攻击者可建立安全通道并读写卡片密钥对象，导致设备克隆或数字钥匙伪造。

### 1.2 本文覆盖

- 产线密钥层级（谁持有、如何派生、如何轮换、如何销毁）
- SCP03 传输密钥的一次性个性化（PUT KEY）与后续轮换（REPLACE KEYS）
- 与当前固件接口的映射及验收判据

### 1.3 不在本文覆盖

- HSM 产品选型与具体 PKCS#11 调用（由信息安全组另行定义）
- SE050 物理侧信道评估、CC/EAL 认证证据
- vSE050 仿真结论不能替代真机与产线证据（见 §9.3）

## 2. 密钥层级

### 2.1 层次总览

```
L0  HSM Root Key (RK)                      仅 HSM 内，不可导出
     └── L1  Manufacturing Master Key (MK) 仅 HSM 内，按产品线划分
          ├── L2  设备传输密钥组 (SCP03 Key Set, 每芯片唯一)
          │        ├── K-ENC[i]  AES-128
          │        ├── K-MAC[i]  AES-128
          │        └── K-RMAC[i] AES-128
          ├── L2  设备身份密钥 (Device Key, 芯片内生成，私钥不可导出)
          │        └── 0x02  ECDSA P-256 / SM2
          └── L3  会话密钥 (每次 SCP03 握手派生，仅 RAM)
                   └── S-ENC / S-MAC / S-RMAC
```

### 2.2 分级属性

| 层级 | 名称 | 算法 | 生成/派生方 | 存储 | 可导出 | 生命周期 | 轮换 |
|:----:|:-----|:-----|:-----------|:-----|:------:|:---------|:-----|
| L0 | Root Key (RK) | AES-256 | HSM 内生成 | HSM | 否 | 产品线建立时 | 仅安全事件后 |
| L1 | Master Key (MK) | AES-256 | HSM 从 RK 派生 | HSM | 否 | 产品线/代际 | 12 个月，旧钥保留 3 个月 |
| L2 | 传输密钥组 | AES-128 ×3 | HSM 从 MK + UID 派生 | SE050 NVM | 仅注入工位临时使用 | 设备生命周期 | REPLACE KEYS，24 个月或泄露时 |
| L2 | 设备身份密钥 | ECDSA P-256 / SM2 | **SE050 内部生成** | SE050 NVM (0x02) | 私钥永不导出 | 设备生命周期 | 换件时重新签发证书 |
| L3 | 会话密钥 | AES-128 ×3 | 双方按 SCP03 派生 | 仅 RAM | 否 | 单次会话 | 每次握手自动更新 |

**原则**：越靠上的密钥越少移动；L2 传输密钥只在首次个性化时以密文形式进入卡片；L3 永不落盘，`close_session()` / `deinit()` 安全清零。

### 2.3 SE050 内部槽位映射

| 槽位 | 代码常量 | 用途 | 当前状态 |
|:----:|:---------|:-----|:---------|
| SCP03 Key Set | (卡片安全域) | K-ENC / K-MAC / K-RMAC，含 key version | ✅ PUT KEY / REPLACE KEYS 已实现 |
| `0x00` | `SE050_SLOT_ROOT_KEY` | 预留根密钥对象 | 预留 |
| `0x01` | `SE050_SLOT_MASTER_KEY` | 预留主密钥对象 | 预留 |
| `0x02` | `SE050_SLOT_DEVICE_KEY` | 设备签名密钥（`sec_sign` 使用） | ✅ 签名 APDU 已实现 |
| `0x10` | `SE050_SLOT_SESSION_KEY` | 会话密钥（RAM 派生，不落盘） | 预留 |

> 应用层透明对象使用 `0xF00000` 起始区间（见 `security.c`），与上述密钥对象分离。

## 3. 派生规则

### 3.1 传输密钥组（HSM 侧，待实现工具链）

```
K_transport[i][key_id] = AES-128-CMAC( MK,
                          0x01 || key_id || UID[i](18B) || version(1B) )

key_id: 0x01 = K-ENC, 0x02 = K-MAC, 0x03 = K-RMAC
UID   : SE050 18 字节唯一标识
```

- 使用 CMAC 而非 ECB，输入长度不受 16 字节限制，且天然具备域分离。
- `0x01` 为域标签（传输密钥组），与后续可能的应用密钥派生区分。
- 每颗芯片、每个 key_id 的结果唯一；HSM 只输出该设备这一组派生密钥，不导出 MK。
- 产线数据库只保存 `UID`、`version`、`key_fingerprint = SHA-256(UID || K-ENC_hash)`，**不保存密钥明文**。

### 3.2 轮换派生（REPLACE KEYS，已实现）

```
new_K(key_id) = AES-128-CMAC( K_old(key_id),
                  0x02 || key_id || old_version || new_version ||
                  nonce(8B) || 0x00 × 4 )
```

- `nonce` 由主机 `crypto_random_bytes()` 生成，经 SCP03 加密通道下发。
- 新密钥**不在总线上传输**，双方各自派生；旧密钥在下次握手时自然失效。
- 代码：`se050_scp03_replace_keys()` / `scp03_derive_replacement_key()`。

### 3.3 会话密钥（已实现）

SCP03 标准派生，`S-ENC/S-MAC/S-RMAC = AES-128(K_i, D_i)`，`D_i` 含 `seq_counter`。每次握手重新计算，关闭通道即清零。

## 4. 生命周期状态机

```
S0 空白 (默认/工厂传输密钥)
   │ 产线：PUT KEY + 设备密钥生成 + 证书签发
   ▼
S1 已个性化 (unique transport key set v1, device key + cert)
   │ 出厂
   ▼
S2 运行中 (SCP03 建链 + 签名/验签)
   │ 计划轮换 / 疑似泄露
   ▼
S3 轮换中 (REPLACE KEYS, version++)
   │
   ├──▶ S2 运行中 (轮换成功)
   └──▶ S4 退役/吊销 (轮换失败、密钥泄露、换件)
```

| 状态 | 允许操作 | 禁止操作 |
|:-----|:---------|:---------|
| S0 空白 | 读取 UID、PUT KEY、生成设备密钥 | 业务签名、证书签发 |
| S1 已个性化 | 建链、证书签发、产线自检 | 重新使用默认密钥 |
| S2 运行中 | 建链、签名、按策略轮换 | 导出私钥、写入陌生密钥组 |
| S3 轮换中 | REPLACE KEYS | 中途断电（需重试或返修） |
| S4 退役 | 证书吊销、对象删除 | 任何密钥使用 |

## 5. 产线注入流程（对齐现有接口）

### 5.1 前置条件

| 项目 | 要求 |
|:-----|:-----|
| HSM | PKCS#11 / CloudHSM，存储 RK/MK，双人授权 |
| 编程工位 | 受控产线，I2C 400kHz；注入固件与量产固件分离 |
| 网络 | 工位 ↔ HSM 走 mTLS；密钥明文不落盘 |
| 人员 | 授权操作员 + 复核员，操作留痕 |
| 固件 | `USE_SE050=ON`，关闭调试口，注入模式一次性使能 |

### 5.2 步骤

| 步骤 | 操作 | 接口/命令 | 判据 |
|:----:|:-----|:----------|:-----|
| 1 | 读取芯片 UID | SE050 Get UID | 非全零，与芯片标签一致 |
| 2 | HSM 派生传输密钥组 | `K_i = CMAC(MK, 0x01‖key_id‖UID‖ver)` | HSM 返回密钥指纹，不返回明文到 DB |
| 3 | 默认密钥建临时通道 | `se050_scp03_init()` + `open_session()` | SW 0x9000，`is_open()==true` |
| 4 | 写入新密钥组 | `se050_scp03_put_key(&s, 0x48, ver=0x01, k_enc, k_mac, k_rmac)` | 返回 `SCP03_OK`，无 SW 错误 |
| 5 | **新密钥重连验证** | `close_session()` → `open_session()` | 新密钥成功；默认全零密钥 `SCP03_ERR_CRYPTOGRAM` |
| 6 | 生成/导入设备密钥 | SE050 内部生成 0x02，导出公钥 | 公钥可验证，私钥不可导出 |
| 7 | 证书签发 | CA 签发设备证书并写入 | 证书链可验证 |
| 8 | 产线自检 | `se050_apdu_sign()` 签名 + 上位机验签 | 64 字节 r‖s，验签通过 |
| 9 | 记录入库 | UID、version、key_fingerprint、operator、时间 | 记录完整、可追溯 |
| 10 | 关闭注入模式 | 清除 RAM 密钥、禁用调试口 | 重启后注入入口不可用 |

### 5.3 时序

```
产线工位                      HSM                     SE050
   │── 读 UID ───────────────────────────────────────→ │
   │←──────────────────────────────── UID(18B) ────────│
   │── Derive(MK, UID) ──→ │                           │
   │←── K_ENC/K_MAC/K_RMAC │                           │
   │                                                   │
   │── SCP03 (默认密钥) ─────────────────────────────→ │
   │←────────────────────────────── 0x9000 ────────────│
   │── PUT KEY (K_ENC/K_MAC/K_RMAC, ver=1) ──────────→ │
   │←────────────────────────────── 0x9000 ────────────│
   │── close + SCP03 (新密钥) ───────────────────────→ │
   │←────────────────────────────── 0x9000 ────────────│
   │── 生成设备密钥 / 签发证书 / 签名自检 ────────────→ │
   │── 记录 UID + 指纹 ──→ 产线 DB                      │
```

> **顺序要求**：必须先完成步骤 5（旧密钥失效验证）再签发证书。否则一旦传输密钥注入失败，设备将带着可被默认密钥访问的卡片进入下游。

## 6. 运行期轮换流程

### 6.1 触发条件

- 例行：每 24 个月（或按 OEM 安全策略）。
- 事件：传输密钥疑似泄露、维修返厂、安全审计要求。

### 6.2 流程

1. 用当前传输密钥建立 SCP03 通道。
2. 调用 `se050_scp03_rotate_keys(&s, 0x48)`：
   - 内部执行 `REPLACE KEYS`（INS 0xD2，key_version + 1），双方用 CMAC 派生新密钥组；
   - 关闭会话并用新密钥重新握手。
3. 验证：旧密钥重连返回 `SCP03_ERR_CRYPTOGRAM`，新密钥签名可用。
4. 更新产线/云端密钥版本记录（只更新 version 与指纹，不保存密钥）。

### 6.3 失败处理

| 失败点 | 处理 |
|:-------|:-----|
| REPLACE KEYS 返回 SW 错误 | 通道保持旧密钥，可重试；连续失败转返修 |
| 轮换后新密钥握手失败 | 视为卡片状态异常，禁止继续业务，走返修/RMA |
| 轮换中掉电 | 用旧密钥重连并重试；无法建链则返修 |

| 能力 | 接口 | 状态 |

| 在线个性化（PUT KEY, INS 0xD8） | `se050_scp03_put_key()` | ✅ |
| 在线派生轮换（REPLACE KEYS, INS 0xD2） | `se050_scp03_replace_keys()` | ✅ |
| 轮换并重建通道 | `se050_scp03_rotate_keys()` | ✅ |
| 设备签名 | `se050_apdu_sign()` / `sec_sign()` | ✅ |
| HSM 派生与产线工位工具 | 待实现（HSM/产线系统） | ⏳ |
| 设备密钥生成/证书签发 | 依赖 Plug&Trust 与 CA | ⏳ |
| 真机 G1 注入/轮换验证 | 见 `docs/g1-bringup-runbook.md` | ⏳ |

**仿真验证**（`test_vse050_scp03`，91/91）：
- PUT KEY 后旧零密钥 `SCP03_ERR_CRYPTOGRAM`，新密钥重连成功；
- REPLACE KEYS 后旧密钥失效、轮换通道签名可用、连续两次轮换；
- 未开通道调用被拒（`SCP03_ERR_CHANNEL`），卡片拒绝（SW 6985）后旧密钥仍有效。

## 8. 验证与判据

| 编号 | 验证项 | 方法 | 频率 |
|:----:|:-------|:-----|:-----|
| KV-01 | 默认密钥失效 | 用全零密钥建 SCP03，应失败 | 每片 |
| KV-02 | 新密钥可建链 | 用注入密钥建 SCP03，应成功 | 每片 |
| KV-03 | 密钥唯一性 | 抽样 1000 片，派生密钥无重复 | 每批次 |
| KV-04 | UID 一致性 | 标签 UID 与芯片读取一致 | 每片 |
| KV-05 | 设备签名 | 签名 + 上位机验签通过 | 每片 |
| KV-06 | 轮换正确性 | 轮换后旧密钥失败、新密钥成功 | 每批次抽检 |
| KV-07 | 密钥不落盘 | 注入固件 RAM 密钥已清零、DB 无明文 | 每版本审计 |
| KV-08 | 侧信道/渗透 | 独立实验室评估 | 每季度 |

## 9. 安全措施与边界

### 9.1 HSM

| 要求 | 说明 |
|:-----|:-----|
| 物理安全 | 受控环境、防篡改封装、FIPS 140-2 L3 或等效 |
| 访问控制 | 双人授权，MK 使用需审计 |
| 轮换 | MK 12 个月；旧钥保留 3 个月仅用于验证 |
| 备份 | Shamir 3-of-5 分片，异地存放 |

### 9.2 产线与固件

| 要求 | 说明 |
|:-----|:-----|
| 密钥传输 | 工位 ↔ HSM 使用 mTLS/专用通道；明文仅存在于注入进程内存 |
| 内存卫生 | 注入完成后 `secure_zero`；注入模式不可在量产固件中启用 |
| 废弃处理 | 注入失败芯片物理销毁（BGA 研磨） |
| 网络隔离 | 注入工位与办公网物理隔离 |

### 9.3 已知边界

- `vSE050` 只验证协议一致性、状态机与错误恢复，**不构成**密钥隔离、侧信道抗性、CC 认证或产线证据。
- 当前 HSM 派生工具、产线工位固件、设备证书签发流程尚未实现，本文为设计基线。
- `se050_scp03_put_key()` 以明文密钥参数接收密钥；仅允许在隔离的注入工位使用，量产运行固件不得调用。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|:-----|:-----|:-----|
| MK 泄露 | 全批次可克隆 | HSM + 双人 + Shamir 分片 + 定期轮换 |
| 注入工位被控 | 单台设备密钥泄露 | 工位隔离、一次性注入、注入模式关闭、行为审计 |
| 默认密钥未替换 | 卡片可被任意读写 | KV-01 每片强制拦截，未通过禁止出厂 |
| 轮换中途失败 | 设备无法建链 | 重试策略 + RMA 流程 + 旧密钥保留窗口 |
| 密钥明文落盘 | 批量泄露 | DB 仅存指纹、注入进程零化、代码审计 KV-07 |
