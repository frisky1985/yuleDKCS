## 2. P0 — 必须通过 (阻塞级)

> 任何一项 P0 测试失败 → HIL 验收不通过 → **版本不可发布**

### 2.1 BLE 连接

| 验收项 | 编号 | 指标 | 测试用例 |
|--------|:----:|:----:|:--------:|
| BLE 广播可达 | HIL-AC-P0-01 | 设备广播名 "yuleDKCS-XXXX" 在 10m 范围内可被 nRF Connect 扫描到 | HIL-BLE-01 |
| BLE 标准连接 | HIL-AC-P0-02 | 手机 App 与 EVB 建立 BLE 连接成功率 = 100% (10 次测试) | HIL-BLE-01 |
| BLE RSSI 有效 | HIL-AC-P0-03 | 0.1m-5m 范围连接成功率 100%, RSSI 数值符合预期范围 (-30 ~ -85 dBm) | HIL-BLE-02 |

**失败影响**: 手机无法发现车辆, 所有 BLE 相关功能不可用  
**重测策略**: 重启 EVB 后重试 2 次, 仍失败则确认为硬件/固件问题

### 2.2 SCP03 安全通道

| 验收项 | 编号 | 指标 | 测试用例 |
|--------|:----:|:----:|:--------:|
| SCP03 标准建链 | HIL-AC-P0-04 | 使用正确密钥 + 自定义密钥 + 默认密钥三种场景均可成功建链 | HIL-SE-01 |
| SCP03 拒绝错误密钥 | HIL-AC-P0-05 | 使用错误 ENC/MAC/DEK 密钥 → SW69 84 (引用数据无效) | HIL-SE-02 |
| SCP03 密钥注入 | HIL-AC-P0-06 | 通过 SCP03 安全通道注入 ECDSA P-256 密钥对, 注入后可成功签名 | HIL-SE-03 |

**失败影响**: 安全芯片不可用 → 所有钥匙操作无安全保障  
**重测策略**: 重新初始化 SE050 (erase + re-inject), 重试 2 次

### 2.3 解锁响应时间

| 验收项 | 编号 | 指标 | 测试用例 |
|:-------|:----:|:----:|:--------:|
| BLE 解锁 < 1s | HIL-AC-P0-07 | 端到端 BLE 解锁 P95 ≤ 1000ms (20 次重复, 含 BLE 传输 + 安全认证) | HIL-UL-01 |
| NFC 解锁 < 500ms | HIL-AC-P0-08 | 端到端 NFC 刷卡解锁 P95 ≤ 500ms (20 次重复) | HIL-UL-02 |

**失败影响**: 用户体验不达标, 不符合产品 PRD 要求  
**归因分析**: 如果失败, 需定位瓶颈 (BLE 传输 / 安全认证 / 执行时间)

### 2.4 NFC 刷卡

| 验收项 | 编号 | 指标 | 测试用例 |
|:-------|:----:|:----:|:--------:|
| NFC 标准刷卡 | HIL-AC-P0-09 | 手机 NFC 靠近天线 0-4cm → 完整 APDU 流程 → 解锁成功 | HIL-NFC-01 |
| NFC 超时回滚 | HIL-AC-P0-10 | 刷卡过程中途移开 → 交易超时 → 重新刷卡可正常完成 | HIL-NFC-03 |

**失败影响**: NFC 作为备用解锁方案不可用  
**重测策略**: 检查 NFC 天线连接, 确认场强检测正常

### 2.5 状态机安全

| 验收项 | 编号 | 指标 | 测试用例 |
|:-------|:----:|:----:|:--------:|
| 非法状态转换阻断 | HIL-AC-P0-11 | 强制状态机跳转到非法状态 → 系统回滚/拒绝 | HIL-FI-05 |
| 系统不崩溃 | HIL-AC-P0-12 | 所有故障注入场景下系统不崩溃, 不进入 HardFault | HIL-FI-01~06 |

**失败影响**: 安全机制失效, 可能被攻击者利用绕过认证

## 5. 联合判断矩阵

| 优先级 | 最大失败数 | 决策 | 响应 |
|:------:|:---------:|------|------|
| **P0** | **0** | ❌ **拒绝** | 必须修复所有 P0 缺陷 → 重测 |
| **P1** | ≤ 2 | ✅ 有条件通过 | 评审影响, PM + Tech Lead 签字 |
| **P1** | ≥ 3 | ❌ **有条件拒绝** | 会议决议, 制定修复计划 → 1 周内重测 |
| **P2** | ≤ 3 | ✅ 通过 | 列入 backlog, 下个迭代修复 |
| **P2** | ≥ 4 | ⚠️ 通过 | 建议下个 sprint 部分修复, 根据资源决定 |

**最终判断公式**:
```
HIL_STATUS = (P0_pass_count == 12) 
           ? (P1_pass_count >= 17 ? PASS : CONDITIONAL_PASS)
           : BLOCKED
```
