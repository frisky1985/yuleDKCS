# yuleDKCS 权限模型参考

> 多车主无需新功能，用现有权限位组合即可实现。

---

## 一、权限位定义

每把数字钥匙携带 8 位权限位图，通过组合实现不同角色：

```
Bit 0: ACCESS_LOCK         — 解锁/上锁车门
Bit 1: ACCESS_ENGINE_START — 启动/停止引擎
Bit 2: ACCESS_TRUNK        — 开启后备箱
Bit 3: ACCESS_WINDOW       — 控制车窗
Bit 4: ACCESS_CLIMATE      — 控制空调
Bit 5: ACCESS_SEAT         — 调整座椅
Bit 6: ACCESS_FUEL         — 开启油箱盖
Bit 7: ACCESS_SHARE        — 可以再分享给他人
```

## 二、角色 = 权限模板

以下角色本质上是预设的权限组合：

| 角色 | 权限位 | 说明 |
|:----|:-------|:-----|
| **车主** | `0xFF` (全部) + 可分享 + 可吊销 | 最高权限 |
| **多车主** | `0xFF` (全部) + 可分享 | **和车主权限一样** |
| **家庭成员** | `0x9F` (除分享外全部) | 可用车但不能把钥匙给别人 |
| **代驾司机** | `0x03` (仅解锁+启动) + 时间限制 | 用完即废 |
| **修车师傅** | `0x05` (解锁+后备箱) + 时间限制 | 仅能开车门和后备箱 |
| **临时访客** | `0x00` (仅NFC刷卡解锁) | 手机没电场景 |

## 三、"多车主"的配置方式

**不需要新功能。** 创建钥匙时选同样的权限组合即可：

```json
// 创建车主2的钥匙 — 跟车主1一模一样的权限
POST /api/v1/keys
{
  "user_id": "车主2的ID",
  "vehicle_id": "同一辆车",
  "access_level": {
    "lock": true,
    "engine_start": true,
    "trunk": true,
    "window": true,
    "climate": true,
    "seat": true,
    "fuel": true,
    "can_share": true    // ← 关键：允许再分享
  }
}
```

这样车主2和车主1拥有对等权限，且车主2也可以分享钥匙给其他人。

## 四、权限组合示例场景

| 场景 | 权限组合 | 有效期 | 
|:----|:---------|:------|
| 夫妻共用 | 全部权限 + 双方都可分享 | 永久 |
| 公司公车 | 全部权限 + 管理员可分享 | 永久 |
| 代驾 | 解锁 + 引擎启动 | 2小时 |
| 修车 | 解锁 + 后备箱 | 4小时 |
| 洗车 | 仅解锁（不能启动） | 1小时 |
| 租车 | 全部权限 | 按天 |
| 儿童 | 解锁 + 空调 | 上下学时段 |

## 五、关键逻辑

```
是否"车主" = 权限位 == 0xFF
"多车主"   = 多个用户都拥有 0xFF 权限
差异点      = 只是权限位的不同组合，不是代码层面的不同角色
```

**所以 yuleDKCS 不需要"多车主"这个新功能。** 现有的 ShareKey API + 8 位权限图 + valid_until 已经完整覆盖了所有场景。
