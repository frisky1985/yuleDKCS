## 1. 目的

规范 yuleDKCS 测试证据的生成、归档与复核，确保所有用于量产评审、ASPICE 与客户审核的证据**真实、可追溯、不可篡改**，杜绝 `docs/hil/HIL-TEST-RESULTS.md` 一类证据失真问题。

## 2. 证据分级

| 等级 | 定义 | 适用 |
|---|---|---|
| **L1 仿真/SIL** | 在主机、QEMU 或仿真器上执行 | 单元测试、软件在环 |
| **L2 硬件在环（HIL）** | 在真实 EVB 或硬件台架上执行 | 外设、射频、功耗、协议端到端 |
| **L3 认证/第三方** | 由认证机构或独立第三方执行 | ICCE/CCC/ICCOA、安全审计 |

L1 证据**不得**替代 L2/L3 用于量产放行。

## 3. 证据必含字段

每条测试证据（报告或 JSON 记录）必须包含：

1. **执行时间戳**（ISO 8601，精确到秒，含时区）；
2. **设备标识**：EVB 序列号、芯片 UID、仪器型号与序列号；
3. **固件版本**：Git commit hash + 配置哈希；
4. **执行环境**：主机/仿真器/真实硬件，明确标注；
5. **原始仪器数据**：不得仅存聚合后的通过/失败结论；
6. **总耗时**：必须与用例标称时长数量级一致（如 300s 用例总耗时不得小于 300s）；
7. **执行人与复核人**签字。

## 4. 一致性校验规则

归档前由质量组执行自动校验：

- 总耗时 ≥ 所有用例标称时长之和（允许仪器启动开销 ≤ 10%）；
- 硬件域用例必须包含真实设备 UID，缺失即判无效；
- 时间戳与设备时钟同步误差 ≤ 1s；
- 同一用例多次运行结果不一致时，以最慢一次为准并记录原因。

校验不通过的证据标记 **VOID**，不得进入评审。

## 5. 归档与哈希

- 证据文件按 `YYYYMMDD-HHMMSS-<test-type>-<device-id>.json` 命名；
- 归档目录 `docs/hil/evidence/`（HIL）、`tests/reports/`（单元）；
- 每个归档批次生成 `SHA-256 manifest`，由复核人签字；
- 历史证据不得删除，只能追加 **VOID** 标记与作废说明。

## 6. 作废流程

证据作废须满足：

1. 发现人提交作废申请，附不一致证据；
2. 质量组复核确认；
3. 在原文件顶部添加 **VOID 标记**，说明作废原因、日期与替代证据位置；
4. 通知所有引用方更新。
